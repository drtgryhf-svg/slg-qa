# 运营/活动质检清单

适用场景：活动配置上线前、商店改价/上新礼包、赛季/KvK 切换、节假日运营。SLG 运营事故大多出在**时间口径**和**奖励数值**，前两节权重最高。

## 1. 时间与展示（SLG 最大雷区）

- [ ] **时间基准三口径**：配置用 UTC、展示用服务器时间、玩家理解成本地时间——三者换算关系在配置和 UI 中一致，且文案标注了口径（"Server Time (UTC)"）
- [ ] 夏令时切换日（3 月/11 月、南半球 10 月/4 月）开的活动，边界时间人工重算
- [ ] 跨天/跨月边界：活动在 23:59 结束时的结算邮件、奖励领取窗口
- [ ] 倒计时显示与实际结束时间一致（显示还剩 8 小时实际已结束 = 经典时区 bug）
- [ ] 全链路窗口：预告 → 开启 → 进行中 → 结算 → 补发，各阶段 UI 与功能正确
- [ ] 活动提前下架/延长时的配置开关与公告预案

## 2. 奖励与数值

- [ ] 奖励表逐行核对：物品 ID、数量、上限（不要出现负数、0 数量、超上限溢出）
- [ ] 概率类：各档概率总和 = 100%（浮点求和留 ±0.01 容差），期望值与运营给的数值表一致
- [ ] 递进/里程碑奖励顺序正确，档位不跳、不重
- [ ] 补发邮件：附件与配置一致、标题正文走 LQA、**幂等校验**（重复领取/重复发信不能发生）
- [ ] 数值生效实测：描述 buff（+10% 行军速度）与战斗/行军实测数值一致（by/to 语义见 lqa-checklist.md）
- [ ] 资源产出/消耗平衡：活动商店兑换价格 × 可获取代币，玩家不会 白嫖溢出 或 无法清空

## 3. 商店 / IAP

- [ ] 商品 ID 与商店后台一一对应，无错挂商品（**礼包内容挂错是 S2**）
- [ ] 价格档位与币种：多币种显示正确、折扣角标计算正确（原价划线 vs 实付）
- [ ] 首充：双倍奖励标记、重置逻辑、已购玩家的显示状态
- [ ] 月卡/战令：购买 → 立即发放 → 每日领取 → 到期 → 续购 全链路
- [ ] 限购次数（终身/每日/每周）在 UI 显示与后端校验一致
- [ ] 掉单恢复：支付成功但未发货时（断网/杀进程）重新登录能补发
- [ ] 退款处理：退款后道具回收策略不会把玩家打成负数资源

## 4. SLG 特有场景

- [ ] **KvK/赛季**：报名资格（王国/个人战力门槛）、匹配规则文案与实际分组、赛季结算奖励发放、新赛季数据清零范围（哪些保留哪些重置——玩家最敏感）
- [ ] **联盟活动**：集结/援助/联盟礼物/联盟商店 在活动期的加成与正常期无串档
- [ ] **排行榜**：结算快照时间点（不要用实时榜当结算榜）、并列名次处理、跨服榜显示、领奖资格边界（刚好第 100 名）
- [ ] **开服节奏**：新服 7 日活动链、新手保护期与活动冲突（护盾期被集结）
- [ ] **迁城/地图**：活动限定迁城道具、飞区（zone）边界规则
- [ ] 服务器合并（merge）：合并前后排行榜/联盟/邮件/城堡位置的保留与转换规则

## 5. 文案与触达

- [ ] 活动名/规则/弹窗/横幅 全部走一遍 LQA（引用 lqa-checklist.md，重点：A 类跑脚本 + B 类数值语义）
- [ ] 推送文案：各语言齐全、时区合理（不要对欧洲玩家凌晨推送）、跳转 deep link 到正确活动页
- [ ] 公告富文本：HTML/富文本标签不炸版、多语言公告同步发布
- [ ] 规则说明的**歧义审查**：玩家会抠字眼的地方（"累计充值"是否含首充、"赛季结束前"含不含最后一天）——有歧义的文案按 S4 提出修改建议
